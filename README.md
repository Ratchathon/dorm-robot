# หุ่นยนต์จดมิเตอร์ + ระบบหอพัก

> **เริ่มเร็ว:** ลองบนโน้ตบุ๊ก → ดับเบิลคลิก `start_demo.bat` · ขึ้นใช้งานจริง → อ่าน `DEPLOY.md`

```
robot/   รันบน Raspberry Pi บนตัวหุ่น : หน้าควบคุม, ภาพสด, ส่งคำสั่งไป ESP32, เก็บค่ามิเตอร์แล้วส่งขึ้น cloud
cloud/   รันบนเซิร์ฟเวอร์ที่เปิดตลอด 24 ชม. : หน้าผู้ดูแล, หน้าลูกบ้าน (ลิงก์ลับรายห้อง), เครื่องคำนวณ
```

## ภาพรวมการทำงาน

1. ผู้ดูแลเปิด `http://<IP ของ Pi>:5000/` จากโน้ตบุ๊กที่ต่อฮอตสปอตเดียวกับหุ่น
2. ขับด้วยคีย์บอร์ด (W A S D, ↑ ↓, 1 มองพื้น, 2 มองผนัง, E พัดลม, Space ถ่าย, Esc หยุดฉุกเฉิน)
3. กดถ่าย → เลือกน้ำ/ไฟ → เลือกห้อง → พิมพ์เลข (มีค่าครั้งก่อนให้เทียบ และเตือนถ้าผิดปกติ)
4. Pi เก็บภาพ+ค่าไว้ในเครื่องก่อน แล้วส่งขึ้น cloud เองเมื่อมีอินเทอร์เน็ต (ส่งซ้ำได้ไม่เกิดข้อมูลซ้ำ)
5. ผู้ดูแลตรวจ/แก้เลขบนเว็บ cloud, ลูกบ้านสแกน QR หน้าห้องเพื่อดูภาพมิเตอร์และยอดของห้องตัวเอง

## ความปลอดภัยที่ทำไว้

| ส่วน | วิธี |
|---|---|
| ควบคุมหุ่น | ใช้ได้เฉพาะในวงแลน/ฮอตสปอต, ขับได้ทีละ 1 เบราว์เซอร์, ข้อความผิดรูปแบบไม่ทำให้ระบบล้ม, เงียบเกิน 0.5 วิ หรือหลุด → หยุดล้อและพัดลม (มุมกล้องคงเดิม) |
| ผู้ดูแล | รหัสผ่านเดียว, cookie แบบ HttpOnly/SameSite, จำกัดการเดารหัส 5 ครั้ง/10 นาที |
| ลูกบ้าน | ลิงก์ลับสุ่มต่อห้อง ดูได้แค่ห้องตัวเอง; "ผู้เช่าใหม่ย้ายเข้า" = ลิงก์เก่าใช้ไม่ได้และไม่เห็นภาพของผู้เช่าเดิม |
| หุ่น → cloud | `DEVICE_KEY` ใช้ได้แค่ดูรายชื่อห้องและเพิ่มค่ามิเตอร์ ลบ/แก้/ดูข้อมูลลูกบ้านไม่ได้ |
| ข้อมูล | แก้เลข/ย้ายห้อง/ลบ เก็บประวัติทุกครั้ง (ลบแบบซ่อน ไม่ลบไฟล์จริง) |

## ติดตั้งบน Pi (robot/)

```bash
sudo apt install -y python3-picamera2 python3-opencv
pip install -r requirements.txt --break-system-packages
sudo systemctl disable --now camera-streamer     # ตัวของ Arducam แย่งกล้อง
cp .env.example .env && nano .env                # ใส่ CLOUD_URL, DEVICE_KEY, ROOMS
python3 server.py
```
ให้รันเองตอนเปิดเครื่องและเปิดได้ที่ `http://meterbot.local:5000`: `bash setup_pi.sh` (ดู DEPLOY.md)

ลองบนโน้ตบุ๊กโดยไม่มีหุ่น: `ROBOT_FAKE_HARDWARE=1 python3 server.py` แล้วเปิด http://localhost:5000

**ต้องปรับบนหุ่นจริง:** `TILT_FLOOR` / `TILT_WALL` ใน `.env` ให้ตรงมุม servo ที่เห็นมิเตอร์น้ำ (พื้น 5 ซม.) และมิเตอร์ไฟ (ผนัง 60 ซม.)

## ติดตั้ง cloud (cloud/)

ต้องการ: Python 3.11+, Postgres (หรือ SQLite สำหรับทดลอง)

```bash
pip install -r requirements.txt
cp .env.example .env    # ตั้ง ADMIN_PASSWORD, SECRET_KEY, DEVICE_KEY, DATABASE_URL
uvicorn app.main:app_from_env --factory --host 0.0.0.0 --port 8000
```
ขึ้นออนไลน์ฟรีด้วย Render + Neon: ทำตาม **DEPLOY.md** (รูปมิเตอร์เก็บในฐานข้อมูล ไม่ต้องมีดิสก์ถาวร)
ต้องใช้ HTTPS ในการใช้งานจริง (cookie ตั้ง `Secure` ไว้แล้ว; ทดลองแบบ http ให้ตั้ง `SECURE_COOKIES=0`)

เริ่มใช้งาน: เข้า `/admin` → แท็บ "ห้องและลิงก์ลูกบ้าน" เพิ่มห้อง → "ราคาต่อหน่วย" ใส่ราคาตามสัญญา → พิมพ์ QR ติดแต่ละห้อง

## การคิดเงิน

- ยอดต่อเดือน = (เลขล่าสุดของเดือนนี้ − เลขล่าสุดก่อนเดือนนี้) × ราคาต่อหน่วย ปัดเศษสตางค์แบบปัดครึ่งขึ้น
- เดือนตามเวลาไทย; ถ้าเลขน้อยกว่าครั้งก่อน ระบบไม่คิดเงินจนกว่าผู้ดูแลจะแก้เลขหรือยืนยัน "มิเตอร์วนรอบ"
- เดือนแรกของแต่ละมิเตอร์เป็น "ค่าฐาน" (ยังไม่คิดเงิน)
- ถ้านาฬิกา Pi คลาดจากนาฬิกาโน้ตบุ๊กเกิน 10 นาที (ไม่มีเน็ต/แบต RTC) จะใช้เวลาของโน้ตบุ๊กแทน

## เปลี่ยนจากโค้ดเดิม

- `camera_stream.py` → `app.py` + `frames.py` (กล้องมี thread เดียว ผู้ชมหลายคนไม่ทำให้ FPS ตก), เลิกใช้ `Access-Control-Allow-Origin: *`
- `Web_test.html` → `static/cockpit.*` (เสิร์ฟจาก Pi เอง ไม่ต้องฝัง IP, ไม่มีปัญหา CORS/canvas)
- `drive_uploader.py` ไม่ได้ใช้แล้ว: ภาพไปอยู่บน cloud ที่คุมสิทธิ์รายห้องได้ (Drive ทำไม่ได้) — และควรยกเลิก `token.json` เดิมที่มีสิทธิ์ Drive ทั้งบัญชี
- `meter_reader.py` (OCR) ไม่ได้ใช้ใน flow หลัก ผู้ควบคุมพิมพ์เลขเอง; ถ้าจะใช้ภายหลังให้เป็น "ค่าแนะนำ" ในช่องกรอก
- โปรโตคอล JSON ไป ESP32 เหมือนเดิม ไม่ต้องแก้เฟิร์มแวร์
